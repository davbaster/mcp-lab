# Configuration and secrets

The notes server has two settings that you may want to change: where the database lives and which folder it may read and write files in. You should not have to edit the code to change them. Step 4 reads them from environment variables.

<CodeSteps step="4" file="server.py" />

The lifespan reads `NOTES_DB_PATH` and `NOTES_DATA_DIR` with `os.environ.get(name, default)`. Without them the server behaves as before: `notes.db` and a `data` folder in the current directory. The data folder is resolved to an absolute path and created if it does not exist. Both settings are read inside the lifespan, when the server starts and not when the file is imported. That is what lets the tests in lesson 3 set them first. The `conftest.py` fixture now sets both variables to paths in `tmp_path`.

A client passes variables to the server it launches with the `env` block of its config.

Replace the placeholder paths with real ones. Use absolute paths, because the client chooses the working directory, not you. `NOTES_LOG_LEVEL` is the setting from Chapter 5.

## Secrets

The notes server needs no secret. A server that calls another service would need an API key, and the rules for it are firm:

- **Read it from the environment, inside the lifespan**, with `os.environ["SERVICE_API_KEY"]`. It fails at startup if the key is missing, which is better than failing in the middle of a tool call.
- **Never write it in the code.** Code gets copied, committed and shared.
- **Never take it as a tool argument.** The model fills in arguments, so the key would pass through the conversation.
- **Never log it**, not even at `DEBUG` level. Log that a key was found, not its value.

Put the key in the `env` block of your own config file, and do not commit a config file that holds a real key.
