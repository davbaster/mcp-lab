# Shipping your server

Your server works on your machine. Shipping it means that someone else can install it, run it and connect it to a client without asking you anything. Step 6 prepares the project for that.

<CodeSteps step="6" file="pyproject.toml" />

The project file says what the server is and what it needs. It has a name, a version and a description, and `requires-python = ">=3.10"`. `mcp[cli]==2.3.0` is pinned to an exact version, so that everyone runs the code you tested. The `pytest` pin sits in the `dev` group, which `uv sync` installs and a production install can skip.

To try it as a newcomer would, copy the project to a new folder and run:

```shell
uv sync
uv run server.py
```

`uv sync` creates the environment, and `uv run server.py` starts the server over stdio. If you share the project, include the `uv.lock` file that `uv` creates, so the dependencies of dependencies are pinned as well.

## The README

A README answers the questions a user has, in order: what it is, how to install it, how to run it, which settings it reads, and how to connect a client. The most useful part is the ready-to-paste config block. The user replaces the paths and restarts the client.
