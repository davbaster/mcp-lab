## #111 trailing newline in route paths

### What was done
- Every route whose path ends in literal text now rejects a trailing `%0a`. Before, 16 of 18 routes answered `<path>%0a` the same as `<path>`, including register, login, logout, last-lesson, quiz attempts and feedback. The issue as filed listed only 3 GET routes.
- `install_strict_paths(app)` in `backend/app/route_paths.py` changes the end of each such route's regex from `$` to `\Z`. Python's `$` also matches just before a final newline. It is called on the last line of `backend/app/main.py`.
- New `backend/tests/test_route_paths.py`, built from `app.routes`, so a new route is checked automatically.
- No API change.

### Decisions made
- The scope covers all 16 routes, not only the 3 in the issue, because it is the same bug.
- Routes ending in a parameter (`lessons/{lesson_id}`, `assets/{file_name}`) are left alone. A newline there becomes part of the ID and gets the route's own 404. A test lists these two, so a new parameter-ending route, for example `{n:int}`, needs a decision.
- A blanket middleware was rejected because it would replace `lesson_not_found`, `asset_not_found` and `chapter_not_found` with the generic `not_found`.

### Open threads
- `install_strict_paths` does not handle a route that ends in a constrained converter. None exists today, and the guard test catches one if it is added.

### Errors
- A container restart stopped the first QA run. QA was run again from the start.

## #28 and #29 Chapter 3

### What was done
- Added Chapter 3, "Building tools: the notes CRUD" (`03-tools`) to `course.yaml` and `ids.json` (`ids:update`): six code steps, six lessons and a five-question quiz.
- Steps: 1 `storage.py` (sqlite3), 2 five CRUD tools with weak docstrings, 3 LLM-ready docstrings, 4 `Note` TypedDict, 5 `ToolError` for not-found, 6 `ToolAnnotations`. Lesson 3 shows steps 2 and 3 side by side in `Tabs`.
- Every step was run from a copy outside the repo with a stdio client: `tools/list` and each tool called, including not-found, bad input and a SQL-looking title. Step 6's annotations were read from `tools/list`.
- Quiz correct answers are b, c, a, c, b as in the spec. `validate`, `ids:check`, `npm test` (2057 passed), `npm run lint` and `npm run build` all pass with 0 errors.

### Decisions made
- In `mcp` 2.3.0 a raised `ValueError` does not give the model its message: the client gets `isError: true` with only `Error executing tool get_note`, and the traceback goes to the server log. Only `ToolError` (`mcp.server.mcpserver.exceptions`) passes the message through: `Error executing tool get_note: Note 42 not found`. Step 5, lesson 5 and quiz question 2 use `ToolError` (the spec said `ValueError`); lesson 5 warns about the difference. The question text says `ToolError("Note 42 not found")`.
- Structured output as run: a bare `Note` gives `structuredContent` equal to the object; `list[Note]` and `Note | str` are wrapped as `{"result": ...}`; an untyped `dict` return has no `structuredContent` at all. Lesson 4 shows a real captured result.
- Step 4 keeps `Note | str` for not-found (the text message stays valid); step 5 returns plain `Note`, and `delete_note` returns `None` (the client sees empty `content` and `structuredContent` of `{"result": null}`).
- Step 6 sets `read_only_hint=True` on `list_notes` and `get_note`, and `read_only_hint=False, destructive_hint=True` on `delete_note`. `ToolAnnotations` is imported from `mcp.types`.
- Argument descriptions from the `Args:` docstring section do not appear in the input schema, only inside the tool description, so lesson 3 says that and no more.
- Quiz question 4 got a decorator line in its snippet; question 5's option is quoted in YAML because of the colons.

### Open threads
- Tried on Linux only; Windows and macOS not tried. The Inspector was not opened for this chapter; the lessons describe results from the stdio runs.
- Not-found raising `ToolError` in step 5 means the server logs each one at INFO; that is expected.

### Errors
- First draft of step 5 used `ValueError` as specified and the real run showed the message was hidden. Fixed by switching to `ToolError` before the lessons were written.
