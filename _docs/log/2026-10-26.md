## #107 course loader edge cases

### What was done
- Course, chapter, and lesson IDs are limited to 100 characters (`MAX_ID_LENGTH` in `backend/app/courses.py`). A longer `COURSES` entry, or a longer manifest chapter or lesson ID, is a `CourseLoadError` that names the entry or the field. A `COURSE_BUILD_DIR` with a path part over the file system limit is the usual "is not an existing folder" error. None of these is a raw `OSError` now.
- The lifespan puts back the catalog that was on `app.state` before it started (or removes it if there was none), so nested `TestClient(app)` blocks no longer break each other.
- The two dot-segment tests assert one exact code per case. A new test calls the ASGI app with `..` and `.` as typed and asserts `course_not_found`.
- No API change: `openapi.yaml` and the client are unchanged.

### Decisions made
- The limit is 100, the same as the request side (`ID_MAX` in `feedback_routes.py`). A pattern error comes before a length error.
- The manifest and `COURSE_BUILD_DIR` cases (section B of the grooming) are in this task, since they are the same `OSError` from the same file.
- The raw `..` test runs in-process through an ASGI scope, not on a real port.
- David decided on 2026-10-26: after the frontend phase, do #107, then #111, then #108. He also asked to file #135 (a content-build warning when a code fence or quiz snippet language won't be highlighted).

- Nested lifespans replace the global metrics object, so after the inner block exits no metrics object is active. Requests still work. Not filed yet.
- Other unreadable-file `OSError`s in the build folder are still raw (not reachable in the deployed image).

## #111 trailing newline in route paths

### What was done
- Every route whose path ends in literal text now rejects a trailing `%0a`. Before, 16 of 18 routes answered `<path>%0a` the same as `<path>`, including register, login, logout, last-lesson, quiz attempts and feedback. The issue as filed listed only 3 GET routes.
- `install_strict_paths(app)` in `backend/app/route_paths.py` changes the end of each such route's regex from `$` to `\Z`. Python's `$` also matches just before a final newline. It is called on the last line of `backend/app/main.py`.
- New `backend/tests/test_route_paths.py`, built from `app.routes`, so a new route is checked automatically.
- No API change.

### Decisions made
- The scope covers all 16 routes, not only the 3 in the issue, because it is the same bug.
- Routes ending in a parameter (`lessons/{lesson_id}`, `assets/{file_name}`) are left alone. A newline there becomes part of the ID and gets the route's own 404. A test lists these two, so a new parameter-ending route, for example `{n:int}`, needs a decision.
- A blanket middleware was rejected because it would replace `lesson_not_found`, `asset_not_found` and `chapter_not_found` with the generic `not_found`.

### Open threads
- `install_strict_paths` does not handle a route that ends in a constrained converter. None exists today, and the guard test catches one if it is added.

### Errors
- A container restart stopped the first QA run. QA was run again from the start.
