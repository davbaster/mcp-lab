### Decisions made (and why)
- A `gateway` container (Caddy) per project is the only service on the `proxy` network. The backend cannot join it and keep port 9000 off it (Docker networks expose every port), so the gateway routes `/api/*` and everything else inside the project. The site file therefore has one upstream per deployment and does the `/metrics` 404 as well. This moves the `/api` vs frontend split out of the site file, which differs from the issue's wording ("all routing in the site file").
- Staging's and production's Postgres are separate containers with their own `db` networks. Isolated deployments reuse another project's server through `DB_NETWORK` and an empty `COMPOSE_PROFILES`. A new database lets every role connect by default (checked), so the README revokes `CONNECT` from `PUBLIC`.
- Caddy's own metrics are served by a `:9180` site with `metrics /metrics` in the shared Caddyfile plus the global `metrics` option (not the deprecated `servers { metrics }`), so the admin API is not exposed to the proxy network.
- HSTS is `max-age=31536000` without `includeSubDomains`, because the server hosts other apps.
- `make check-caddy` needed a Makefile target because a test requires every workflow `run:` to be `make <target>`. `.gitattributes` and `.gitignore` also got a few lines (LF for `*.caddy` and `deploy/**`; `deploy/*.env` ignored). The throwaway values for validation are in `deploy/caddy-validate.vars` because a test forbids `.env` in the Makefile.
- The media CDN origin was not changed: the provider needs David's approval, so `content-build/media-config.json` still holds the placeholder.

## #34 QA fix: isolated env file

### What was done
- `docker compose config -q` failed on an isolated env copy without `POSTGRES_*`, because the postgres service's required variables are interpolated even when its profile is off. `POSTGRES_USER`, `POSTGRES_PASSWORD`, and `POSTGRES_DB` now default to empty in `deploy/compose.yaml`. The postgres image refuses to start without a password, so a missing value in production or staging still fails loudly, and `DATABASE_URL` stays required.
- The shared `db` network is now `external: ${DB_EXTERNAL:-false}`; the isolated example sets `DB_EXTERNAL=true` (README step 2 and both env examples updated).
