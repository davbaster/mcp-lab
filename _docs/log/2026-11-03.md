## #41 Redaction module

### What was done
- Added `oncall-mcp/oncall_mcp/redaction.py`: `redact(value)` and `KINDS`, standard library only. Key-based layer (whole value replaced under password, token, cookie, email, username and quiz-answer keys) and a text layer (header lines, Bearer, GitHub/Anthropic tokens, JWTs, URL userinfo, `key=value` pairs, emails), with JSON written inside JSON strings parsed, redacted and written back. Added a "Redaction" section to `oncall-mcp/README.md` and a line in `HANDOFF.md`.
- Checked with a throwaway script outside the repo (1244 checks: every row of the issue as a field, nested and in free text, the tricky cases, idempotence including 30,000 random strings, unchanged non-sensitive values, and 1 MB timings including adversarial shapes). `make lint-oncall-mcp` and `make lint` pass.

### Decisions made
- No test files and no pytest, per David (2026-10-26, confirmed for #41 on 2026-11-03), so the issue's "and tests" is not met by design.
- `session` as a dict key is a `token`, but `session=...` in text is a `cookie`. `user` matches a key only exactly. A sensitive key replaces its value with the marker whatever the type. Depth beyond 50 and self-referencing containers become `[REDACTED:token]`.
- Text patterns are split by kind and use string templates (no Python callback per match), because a callback cost about 3 microseconds per match and a 1 MB string of 100,000 matches took over 200 ms.
